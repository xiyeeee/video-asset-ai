# Python 分镜提取开发提示词

在 `video-asset-ai` 实现镜头切分、代表帧和分镜清单。先阅读 `AGENTS.md`、[三端契约](../shot-extraction-contract.md)、[现有素材任务协议](../java-asset-extraction-api.md)、`app/pipeline/asset_tasks.py` 和 `app/video/ffmpeg.py`，保留工作区已有改动。按契约交付 Python 端，Java 和前端由各自会话实现。

## 实现范围

1. 在现有素材任务编排中接入 `SHOTS`。复用 FFmpeg/FFprobe 调用、输入路径校验、临时目录校验与发布逻辑。分镜有独立的执行资源和状态，可与人物、音频并行。保持现有人物固定间隔抽帧、音频和旧人物接口的行为。
2. 逐帧分析原视频的相邻画面变化。首版采用 FFmpeg `scdet` 提供候选硬切信号，低分辨率分析时保持源帧时间轴。阈值可配置，用业务样片定默认值。规范化并去重边界，按契约输出覆盖整段的半开区间。避免把 2 秒采样、字幕变化或闪白直接当作切镜规则，记录转场的已知限制。
3. 每个镜头从接近区间中点的实际帧生成一张 JPEG，保留该帧的真实 `previewTimestampMs`。无切点的有效视频输出一段。对于很短镜头、非零流起点或可变帧率，仍按源视频播放时间校验代表帧落在镜头内。
4. 生成契约中的 `shots.json` 和缩略图目录，验证清单关系及引用文件后一次发布。按约定报告阶段、计数及稳定错误码，按任务 ID 记录耗时。新工具放在现有模块边界内，`SHOTS` 分支直接复用。

## 验证

- 用合成视频验证已知切点、无切点、一段短镜头和实际代表帧时间。覆盖任务幂等，至少确认分镜失败时其他成功分支可读取。
- 运行 Ruff 检查、格式检查与 pytest。用真实 HTTP 提交 `outputs:["SHOTS"]` 及与音频的组合。优先使用《末班车之后》样片，核对切点和预览画面，报告误切、漏切与不可用的样片或模型条件。
- 交付可读取的真实 `shots.json` 路径、代表图和可复现命令。示例字段须与三端契约一致，发现契约需要变更时回报差异，由三端同步修订。
