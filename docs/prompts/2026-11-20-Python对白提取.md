# Python 对白提取开发提示词

在 `video-asset-ai` 实现离线对白识别。先阅读 `AGENTS.md`、[对白提取三端契约](../dialogue-extraction-contract.md)、现有素材编排和 WAV 导出代码。Java 和前端由各自会话实现，直接按同一份契约交付真实服务。交付条件见契约的「真实联调与交接」。

## 实现范围

1. 添加 `DIALOGUE` 分支。复用 FFmpeg 音轨提取、共享目录、任务状态和原子发布。同一 Python 任务同时选择 `AUDIO` 和 `DIALOGUE` 时共享一次原音轨解码，音频分支可先发布。保持已有 WAV 格式、人物和分镜接口行为，避免分支互相等待同一个执行线程。
2. 首版在 Apple Silicon 上用 CPU 试跑 FunASR 的 `paraformer-zh`、`fsmn-vad` 和 `ct-punc`，读取句级转写和时间戳。通过现有 uv 方式接入实际验证过的 Python 3.11 依赖，记录权重和运行配置。模型按需加载，现有非对白任务可在未安装识别模型的环境运行。
3. 试接 CAM++ 产出匿名说话人编号。按首次出现顺序归一化编号，时间仍对齐原视频。模型缺少说话人结果或聚类失败时，保留有效转写并使用 `speakerId:null`。明确报告实测说话人分组的质量。
4. 按契约生成 `dialogue.json`，校验实际时间范围、顺序、文本和句段数量后再发布。核对模型输出时间单位和 VAD 偏移，验证延迟音轨在播放器时间轴上的位置。区分无音轨、无语音、模型失败。任务 ID 贯穿日志。

## 开发与联调安排

本轮先完成代码和本端必要检查，按共用契约实现正式接口。三端各自开发，不等待其他端，不启动整链路联调。交付时汇报文件、现有检查结果、启动配置和后续联调入口。本端独立检查包括下列项目。

- 覆盖对白与音频同单复用、无音轨、静音成功、延迟音轨、未知说话人和部分失败。运行 Ruff 检查、格式检查及 pytest。

## 收到通知后集中验收

等用户确认三端都已完成开发，再执行下列真实联调。三端使用同一集带人声的原视频，测试示例仅用于字段核对和本端独立测试。

- 优先试听《末班车之后》，确认有可辨人声。若样片只有配乐或烧录字幕，换成项目中有实际配音的剧集，并让三端使用同一个源视频。用真实 FunASR 权重通过 HTTP 完成受理、轮询和发布。核对原始音频、转写、说话人交替和句段起止时间。
- 向 Java 交接实际服务地址、运行配置、共享目录、`sourceVideoRef`、成功任务 ID、`manifestRef` 和句段数量。交接的清单必须由真实 Python 主流程生成。Java 发起自己的真实执行任务后，用其 Python 执行 ID 复核结果，确保两边字段、时间戳和数量一致。
- 依赖尚未就绪时，先交付当前已验证的阶段并列出具体阻塞。真实调用通过后再更新联调结果。
