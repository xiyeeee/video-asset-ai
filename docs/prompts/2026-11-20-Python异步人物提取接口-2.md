\# video-asset-ai｜交付异步人物提取接口\
\
在现有 video-asset-ai 仓库中完成或验收异步人物提取接口。先阅读 AGENTS.md、已有实现和对接文档，复用已通过验证的 FFmpeg 抽帧、Grounding DINO 检测和 SAM 2 分割流程，保持现有 CLI 可用。\
\
1\. 提供 POST /internal/v1/character-extraction/tasks 和 GET /internal/v1/character-extraction/tasks/{taskId}。提交参数为 Java 生成的 taskId、相对共享输入根目录的 sourceVideoRef，以及可选的 frameIntervalSeconds。首次受理返回 HTTP 202，耗时处理在后台执行。\
2\. 同一 taskId 和相同有效参数重复提交时返回已有状态，并发提交只执行一次。相同 taskId 对应不同参数返回 409。任务查询返回 QUEUED、RUNNING、SUCCEEDED 或 FAILED，以及当前阶段。不存在的任务返回 404。\
3\. 成功时返回 manifestRef 和 characterAssetCount。characters.json 中每项包含来源帧、实际帧时间戳 timestampMs、人物框、检测分数和透明 PNG 文件引用。人物编号只在当前帧内有效。无人帧或零素材结果可正常成功。失败时返回稳定的错误码和可读消息。\
4\. 使用可配置的共享输入、输出目录，验证文件引用解析后仍在对应根目录内。每个任务独立写入，清单与图片校验通过后发布结果，再更新为 SUCCEEDED。日志用 taskId 串起各阶段和耗时。沿用现有部署约定，并明确进程重启后任务状态和已落盘结果的处理方式。\
5\. 更新 docs/java-character-extraction-api.md，写清实际接口、请求及响应示例、状态和错误码、幂等规则、共享目录配置，以及 manifestRef 和清单内各文件路径分别相对哪个目录。附一份实际生成的 characters.json 示例，供 Java 直接核对。\
6\. 运行 Ruff 和相关测试，再启动服务，用短漫剧通过 HTTP 实际提交并轮询，核对透明 PNG、文件引用和实际帧时间戳。汇报验证结果，明确区分真实模型与模拟验证。\
