你正在开发「视频转素材」项目的 Python 服务。本轮实现 Live2D 组合动作编译。先阅读现有模型构建、动作生成与 Java 调用入口，拿一份实际生成的模型检查能使用的参数。复用现有框架、数据模型和产物格式。\
\
1\. 明确模型能力\
&#x20;  读取现有模型生成链路提供的参数清单或绑定信息，明确这份模型能控制哪些参数、参数范围及默认值。参数名称、模型版本和动作能力以实际产物为准。模型缺少手臂或手型绑定时，返回结构化的缺失能力，供 Java 转发给前端。\
\
2\. 编译多轨动作\
&#x20;  输入包含 modelVersionId、总时长及轨道片段。片段包含 clipId、轨道类型、sourceId、startMs、durationMs。已保存动作还需要可定位到其具体版本或不可变产物。\
&#x20;  起始时间、时长统一用整数毫秒。输出当前播放器实际能消费的参数曲线或动作文件，并返回格式版本、时长和诊断信息。时间轴上不同参数可以同时生效。片段结束后按约定恢复默认值或淡出，避免上一片段的姿态残留。\
\
3\. 处理参数冲突与口型\
&#x20;  首版支持眨眼、微笑、点头和基础说话口型。用实际绑定把眼睛、头部角度、嘴形和嘴巴开合映射到对应参数。说话口型可根据台词音频的幅度生成开合曲线，并对齐音频片段起点。\
&#x20;  当模型有独立嘴形参数时，微笑控制嘴形，口型控制开合。当两个片段在重叠时间写同一个参数、且无法按已知规则拆分时，返回冲突的参数 ID、片段 ID 和重叠区间，由用户调整后重新预览。缺少必要参数时同样返回明确诊断。\
\
4\. 联调与验收\
&#x20;  使用实际模型和台词样本验证：同一时刻能看到微笑、点头、嘴巴开合；音频未开始时口型尚未开始；拖到组合末尾时最终姿态可正确计算。额外验证同参数冲突和缺少手部绑定。\
&#x20;  与 Java 对齐请求、响应、错误码和产物读取方式，提供一份真实请求及返回样例。复用已有任务和日志机制，记录任务 ID、模型版本 ID 和失败阶段。\
