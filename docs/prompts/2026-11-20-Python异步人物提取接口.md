\# video-asset-ai：封装异步人物提取任务接口\
\
在现有 video-asset-ai 项目中实现本轮功能，遵守仓库的 Python 开发规范。\
\
本轮目标是让 Spring Boot 后端 video-asset-server 能通过 HTTP 提交人物提取任务、轮询进度，并获取透明 PNG 和原视频时间戳。复用已验证的 FFmpeg 抽帧、Grounding DINO 人物检测和 SAM 2 抠图逻辑。改动范围限于 Python 服务及 Java 对接文档。\
\
\## 1. 复用现有人物提取流程\
\
\- 先检查现有抽帧 CLI、人物提取 CLI、frames.json 和 characters.json 的实际结构。将可复用的处理逻辑放在业务模块，由 CLI 和 HTTP 任务共同调用，保持原有 CLI 用法兼容。\
\- 执行顺序为「读取原视频 → 抽帧 → 人物检测 → SAM 2 抠图 → 写入结果清单」。复用现有抽帧参数和模型配置。\
\- 人物素材按帧返回。人物编号沿用现有约定，每条素材保留实际帧时间戳 timestampMs、人物框、检测分数和透明 PNG 文件引用。跨镜头角色归组留到后续迭代。\
\
\## 2. 提供 FastAPI 任务接口\
\
\### POST /internal/v1/character-extraction/tasks\
\
示例请求：\
\
{\
&#x20; "taskId": "task-001",\
&#x20; "sourceVideoRef": "uploads/episode-01.mp4",\
&#x20; "frameIntervalSeconds": 2\
}\
\
\- taskId 由 Java 生成。sourceVideoRef 是相对共享输入目录的文件引用。frameIntervalSeconds 可选，默认复用现有抽帧配置。\
\- 校验参数和源文件引用。任务受理后立即返回 HTTP 202 及初始任务状态，抽帧和模型推理在后台执行。\
\- 同一个 taskId 和同一份有效参数重复提交时，返回已有任务状态，并保证并发请求也只执行一次。相同 taskId 对应不同参数时返回 HTTP 409。\
\
\### GET /internal/v1/character-extraction/tasks/{taskId}\
\
\- 返回 taskId、status、stage。status 使用 QUEUED、RUNNING、SUCCEEDED、FAILED。\
\- stage 至少覆盖 EXTRACTING_FRAMES、DETECTING_CHARACTERS、SEGMENTING_CHARACTERS、WRITING_RESULTS。进度可以先用阶段和实际可统计的数量表达。\
\- 成功时返回 result，至少包含 manifestRef 和 characterAssetCount。manifestRef 指向 characters.json，Java 可从共享目录读取清单和透明 PNG。\
\- 失败时返回 error，包含稳定的 code 和可读的 message。服务日志保留异常详情。\
\- 查询不存在的任务返回 HTTP 404。请求参数、源文件缺失、任务冲突和处理失败的响应示例写入对接文档。\
\- 视频处理成功但没有检测到人物时，正常返回 SUCCEEDED 和空素材清单。\
\
\## 3. 后台执行与共享目录\
\
\- 联调使用可配置的共享输入、输出目录。文件引用统一使用相对于对应共享根目录的路径。校验解析后的路径仍在对应根目录下，包括符号链接的情况。HTTP 响应中使用相对引用。\
\- 首版部署按单进程、单后台执行器一次处理一个推理任务。任务状态与重复提交检查可先存在内存中，并在文档中说明进程重启后内存状态会丢失，以及已落盘结果的处理方式。\
\- 每个任务使用独立输出目录。先在临时位置生成结果，校验清单引用的文件均存在后再发布。结果发布成功后才将状态改为 SUCCEEDED。重跑时避免将上次残留文件混入本次结果。\
\- 任务日志用 taskId 串起接收、各阶段开始和完成、失败原因、耗时及素材数量。使用类型标注，并为时间戳、幂等和结果发布等关键逻辑补充简洁中文注释。\
